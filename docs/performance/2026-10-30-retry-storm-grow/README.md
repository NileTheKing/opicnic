# 재시도 폭풍 실험 — 실제 등급 한도(OpenAI Grow) 기준 (2026-10-30)

질문: 전면 장애가 풀린 직후 밀린 재시도가 내 한도를 넘어 429 폭풍이 생기는가. 지수 백오프, jitter, 리미터가 이를 막고 복구를 빠르게 하는가.
2026-09-26 실험(`../2026-09-26/retry-storm.md`)을 현실 규모로 다시 잰 것이다.

## 조건
- VM 실험 앱(지금 코드), 시즌 피크 초당 46문항(제출 13.2건/s), 슬롯 500, 메모리 저장소, 서킷 켬(429는 안 셈).
- 내 한도 = OpenAI 등급표 Grow: STT(gpt-4o-mini-transcribe) 분당 10,000회 / 800만 토큰, LLM(gpt-4o-mini) 분당 30,000회 / 1억 5천만 토큰.
  요청 수 한도와 토큰 한도 중 먼저 차는 쪽에서 429. 호출당 토큰 `CallTokens`(채점 3,250, 태깅 1,500, STT 2,400 — OpenAI 계산 규칙 max(max_tokens, 입력 추정), STT는 가격표 역산).
- 거절도 요청 수 한도를 깎는다(OpenAI 문서 "unsuccessful requests contribute to your per-minute limit"). 토큰은 깎지 않는다(문서에 없음).
- 가짜 제공자 응답: STT 1.5초(실측 80초 녹음 12회 1.3~1.8초), LLM 4.5초(실측 채점 336건 중앙값 3.6 / 평균 5.8초 사이), 태깅 0초.
- 예열 60초 → 전면 장애(전부 503) 300초 → 복구 후 관찰. 설정마다 1회. 실행: `scripts/exp/run-storm.sh`, 요약 `scripts/exp/exp-storm.py`.

| 설정 | 재시도 대기 | 리미터 |
|---|---|---|
| R1 | 즉시 | 없음 |
| R2 | 지수 백오프 + 1초 jitter | 없음 |
| R3 | 지수 백오프 + full jitter | 없음 |
| R4 | full jitter | AIMD(429에 반응, 지금 운영) |
| R5 | full jitter | 미리 세기(요청 수 + 토큰, 등급표 값) |

## 결과 (복구 후 처음 90초, 다섯 실행 공통 구간)

| 설정 | 429 비율(전체) | STT 429 비율 | 외부 호출 | 완료 /s | 복구 시점 대기 줄 |
|---|---|---|---|---|---|
| R1 | 6.5% | 16.6% | 10,668 | 37.3 | 13,928 |
| R2 | 4.3% | 11.4% | 9,912 | 35.3 | 13,984 |
| R3 | 4.2% | 11.0% | 10,269 | 36.4 | 13,990 |
| R4 | 1.3% | 3.5% | 9,643 | 35.3 | 13,966 |
| R5 | 0.0% | 0.0% | 9,690 | 35.9 | 14,019 |

- R1~R4는 복구 후 93~178초에 호스트 여유 메모리 중단 기준(2,048MB, VM에 axon-jaeger 약 9.3GB 상주)에 걸려 멈췄다(2,039~2,046MB). 그래서 공통 구간 90초로 비교했고 적체 해소 시간은 재지 못했다. R5만 끝까지 갔다.
- 429는 STT에서만 났다. 가장 빠듯한 한도가 STT 토큰(필요량 대비 약 1.2배)이라서다.

## 읽은 것
- **429 폭풍은 실제 등급에서도 생기고, 세 장치가 줄인다.** STT 429가 즉시 재시도 16.6% → 지수 백오프 + jitter 약 11% → AIMD 3.5% → 미리 세기 0%.
- **복구 속도(완료 /s)는 다섯 설정이 같다(35~37건/s, 1회 측정의 흔들림 안).** 먼저 차는 한도가 토큰이고 거절은 토큰을 깎지 않으므로(가정), 429가 나도 처리 용량이 줄지 않는다. 이 조건에서 백오프와 리미터는 복구를 빠르게 하지 않고 낭비 호출(429)만 줄인다. 다시 재도 해소 시간 차이는 나지 않을 것이다.
- 복구 시간이 줄어드는 것은 요청 수 한도가 먼저 차는 경우다(거절이 요청 수를 깎아 한도를 낭비). 2026-09-26 실험(초당 10건 요청 한도)이 이 경우였고 복구 270초 → 54초.
- 복구 직후 처음 약 30초는 서킷이 아직 열려 있어(장애 중 열림 98%) 모든 설정에서 처리가 늦다. 처음 90초 완료가 토큰 한도 기준 용량(STT 약 55건/s)보다 낮은 이유로 보인다(분해 안 함).

## 한계
- 설정마다 1회. 거절이 토큰을 깎는지 모름(깎는다면 결론이 바뀔 수 있다). STT 호출당 토큰은 추정. 버스트는 가짜 제공자 5초치(실제 값 문서에 없음). R5는 추정 토큰이 실제와 같아 미리 세기에 유리한 조건.
