# 채점 보정 실험 (2026-10-07)

누가 봐도 AL인 답이 IM2로, IM2인 답이 AL로 나오면 안 된다. 등급을 미리 정해 쓴 답변으로 그걸 잰다.

## 방법

- `anchors.json`: 질문 3개(묘사 TYPE_1 / 기억에 남는 경험 TYPE_4 / 사회 이슈 TYPE_10) × 등급 6단계(IL~AL) = 18개. ACTFL 말하기 기술에 맞춰 작성자가 쓴 기준점이라 공인 채점 결과는 아니다.
- `run.py`: 운영과 같은 프롬프트(LlmService.java, 당시 이름 GroqService에서 그대로 추출)와 같은 공급자 설정(application-<공급자>.yml)로 채점하고, 등급도 FeedbackService와 같은 규칙(점수 5개 평균 → 구간)으로 계산. STT는 거치지 않는다.
- `compare.py`: 등급 일치, ±1단계, 2단계 이상 빗나감, 순서 뒤집힘(같은 질문에서 더 높은 기준점이 더 낮은 등급), JSON 실패, 원문에 없는 인용.

## NH 추가 (level-v3, 2026-10-08) — 운영 채택

v1의 IL 설명("단어·구·외운 표현 위주")은 ACTFL로는 NH였고, IL 기준점도 같은 모양이라 눈금 바닥이 한 칸 밀려 있었다. 바로잡았다:
- 등급에 NH 추가. NH = 단어·구·외운 표현 위주, IL = 짧은 단문을 스스로 만듦(`level-v3.md`).
- 기존 IL 기준점(단어 나열)은 NH로 다시 표시하고, 진짜 IL(짧고 끊기는 단문)을 질문마다 하나씩 새로 썼다 → 개발용·검증용 각 21개.
- NL·NM은 등급으로 주지 않는다 — 그 정도면 판단할 말이 없는 것이라 "채점 불가"로 다룰 일(별도 작업).
- 공급자 설정은 운영과 같은 `application-<공급자>.yml`에서 읽는다(`run.py`).

- 검증용에서 NH·IL이 정확히 맞는다(바닥 눈금이 바로잡힘). 개발용 NH는 IL로 한 단계 높게 나온다.
- 남은 경향은 v1과 같다: IM1~IM3를 한 단계 높게 본다. 기준점이 작성자 판단이라 어느 쪽 탓인지는 여기서 못 가른다.

- Groq(gpt-oss-120b)로는 v3를 재지 않았다.

## 모범 답안을 "내 답을 한 단계 올린 버전"으로 (2026-10-08)

모범 답안이 새로 지어낸 화려한 에세이에 가까웠다(운영 1888번: 162단어, "boasts", "light dance on the wooden tables"). 지시를 바꿨다 — 사용자 소재를 살리고, 위 4개 항목의 고친 문장을 넣고, 한 단계 위 등급 수준의 따라 말할 수 있는 구어체, 80~150단어. `model_answer_check.py`로 쟀다(이전 결과는 `before-model-answer/`).

|---|---|---|---|---|

- 모범 답안은 목표대로 바뀌었다. 길이 상한(150)은 가끔 넘는다(최대 222).
- JSON 실패 2건: 고친 문장 필드 안에 `"원문" -> "고친 문장"`을 통째로 쓴 것 1, 작은따옴표를 `\'`로 escape한 것 1. 뒤의 것은 파싱을 너그럽게 해 받는다(LlmService.parseResponse). 앞의 것은 워커가 INVALID_OUTPUT으로 재시도한다.

통합 프롬프트(+해요체 규칙)를 개발용·검증용에 3번씩(`--level r1/r2/r3`, 126건). 한 번 잰 숫자가 흔들림인지 가리려고.

| r2 | 7/21 | 18/21 | 13/21 | 19/21 | +0.52 / +0.29 |

- IM2~AL이 IH로 몰린다. 2단계 이상 빗나감은 전부 "IM2를 IH로"다. 근거(levelEvidence)를 보면 100단어 안팎의 단문을 시간 순서로 깔끔하게 이은 답을 "하나의 문단"으로 읽는다 — 정돈됨을 문단 수준으로 착각.

## 정답 등급을 실제 OPIc 기준으로 + 등급 설명 재작성 (level v4, 2026-10-08) — 운영 채택

반복 측정에서 "IM2~AL이 IH로 몰림"으로 보였는데, AL 취득자(사용자) 지적으로 **기준점 정답이 실제 체감보다 한 단계 빡빡했다**는 걸 알았다. 등급 공개 영상(DOMAIN.md "실제 OPIc 등급 기준", "실제 등급을 받은 답변 사례")을 근거로 정답을 다시 붙였다.

- 기준점의 `level`은 작성 당시 의도(id)로 두고 `label`에 새 정답을 적었다(이유는 `label_reason`). 실제 IM2 사례보다 낫고 실제 IH 사례보다 단순한 답처럼 글자만으로 한 등급을 못 정하는 경계 답은 범위로 둔다.

| 작성 의도 | 새 정답 |
|---|---|
| NH / IL | 그대로 |
| IM1 | IM1~IM2 |
| IM2 | IM2~IH |
| IM3 | IH~AL |
| IH | AL |
| AL | AL |

- 프롬프트(`prompts/scoring.md` 1절): 말의 단위를 1차 기준으로, "경계에서는 낮은 쪽" 삭제, IM2 = 말은 되는데 MP 없음, IM3는 드물게만, AL은 원어민이 아니라 문단 + 시제·어휘·구조가 안정된 학습자("망설이지 말고 AL"). 모범 답안은 IM3를 건너뛴다(IM2 → IH 수준).

새 정답(`compare.py <태그> --label`)으로 다시 잰 결과:

| | 개발 범위 안 | 검증 범위 안 | 치우침(개발/검증) |
|---|---|---|---|
| 이전 프롬프트 r1~r3 | 13~16/21 | 14~16/21 | -0.19~-0.24 / -0.19~-0.24 |
| **v4** | **18/21** | **19/21** | +0.14 / +0.05 |

- 이전 프롬프트는 범위로 넓혀도 AL 기준점을 IH로 낮게 준다(위쪽이 막힘). v4는 AL을 준다 — AL 기준점 6/6, 작성 IH 기준점 5/6이 AL.
- v4의 빗나감은 아래쪽: 개발 NH→IL 2건, IL→IM1 1건, 검증 IL→IM2 1건(유일한 2단계). 검증 routine IL은 오류 없는 단문 나열이라 새 등급 설명으로는 IM1에 가까운 답이다 — 정답을 고칠 만하지만 검증 세트를 결과 보고 고치면 맞추기가 되므로 그대로 둔다.
- 한계: 1회 측정이다(반복 측정에서 회차별로 3~4개 흔들림). 정답 자체가 영상 사례와 사용자 판단에 기댄 추정이다.
