# 채점 보정 실험 (2026-10-07)

누가 봐도 AL인 답이 IM2로, IM2인 답이 AL로 나오면 안 된다. 등급을 미리 정해 쓴 답변으로 그걸 잰다.

## 방법

- `anchors.json`: 질문 3개(묘사 TYPE_1 / 기억에 남는 경험 TYPE_4 / 사회 이슈 TYPE_10) × 등급 6단계(IL~AL) = 18개. ACTFL 말하기 기술에 맞춰 작성자가 쓴 기준점이라 공인 채점 결과는 아니다.
- `run.py`: 운영과 같은 프롬프트(GroqService.java에서 그대로 추출)로 채점하고, 등급도 FeedbackService와 같은 규칙(점수 5개 평균 → 구간)으로 계산. STT는 거치지 않는다.
- `compare.py`: 등급 일치, ±1단계, 2단계 이상 빗나감, 순서 뒤집힘(같은 질문에서 더 높은 기준점이 더 낮은 등급), JSON 실패, 원문에 없는 인용.

원본: `results-gemini.jsonl`, `results-groq.jsonl`.

## 등급 판단 분리 (level-v1)

등급을 코칭 점수 평균에서 떼어, LLM이 ACTFL 기술(말의 단위 / 시제 운용 / 연결 / 어휘 / 오류의 성격)로 근거(levelEvidence)를 먼저 적고 등급(level)을 고르게 했다(`level-v1.md`, 기존 프롬프트 뒤에 덧붙임). 서버는 단어 수로 상한만 건다(35단어 미만 IM1, 60 미만 IM2, 90 미만 IM3, 120 미만 IH까지).

| gemini-3.5-flash-lite | 기존 규칙 · 개발용 | level-v1 · 개발용 | 기존 규칙 · **검증용** | level-v1 · **검증용** |
|---|---|---|---|---|
| ±1단계 | 11/18 | 17/18 | 12/18 | **17/18** |
| 2단계 이상 빗나감 | 7 | 1 | 6 | **1** |
| 평균 치우침 | +1.17 | +0.72 | +1.06 | +0.67 |
| 순서 뒤집힘 | 0 | 0 | 0 | 0 |
| JSON 실패 | 0 | 0 | 0 | 0 |

- 검증용(`anchors-test.json`, 다른 질문·유형 — 루틴/최근 경험/비교)은 프롬프트를 고치는 동안 보지 않았다. 개발용과 같은 폭으로 좋아져 개발용에 맞춘 효과가 아니다.
- 위쪽 등급이 구분된다: 기존엔 IM3~AL이 전부 AL, v1은 IM3→IH, IH→IH/AL, AL→AL.
- 남은 경향: IM1~IM3 구간에서 한 단계 높게 준다. 기준점 등급은 작성자 판단이라, 모델이 후한 건지 기준점이 보수적인 건지 이 실험만으로는 가를 수 없다.
- v2(경계 판별 규칙 추가, "확신 없으면 낮게")는 개발용에서 나아지지 않아(JSON 실패 1, 순서 뒤집힘 1) 채택하지 않았다.
