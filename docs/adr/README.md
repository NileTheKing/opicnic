# ADR — 아키텍처 결정 기록

결정 하나 = 파일 하나. 지우거나 옮기지 않는다. 결정이 뒤집히면 **새 ADR을 쓰고 옛 ADR의 상태만 바꾼다**(`Superseded by ADR-NNNN`). 오늘의 결정이 왜 나왔는지, 그 전엔 뭘 믿었는지가 그대로 남는다.

## 인덱스

| # | 제목 | 상태 |
|---|---|---|
| [0001](0001-async-r2.md) | 음성 채점 비동기화 + 오브젝트 스토리지(R2) | Accepted 2026-09-17, 미구현 |

기각한 기술 선택(Kafka/Redis/ES 등)은 `../hold.md`에 있다. ADR로 옮길 가치가 있는 건 다시 검토될 때 그때 옮긴다.

## 형식

번호는 4자리 순번, 파일명은 `NNNN-짧은-제목.md`. 상단에 상태·날짜, 본문은 네 절이면 충분하다 — 1인 프로젝트에 그 이상은 과함.

```
# ADR-NNNN: 제목
> 상태: Proposed | Accepted | Deprecated | Superseded by ADR-NNNN (날짜)

## 맥락    — 무엇이 문제였나, 어떤 제약이 있었나 (측정값·실제 사고 포함)
## 결정    — 무엇을 하기로 했나
## 근거    — 왜 이것인가, 대안은 뭐였고 왜 아닌가
## 결과    — 이 결정으로 딸려오는 변경과 정직하게 남는 한계
```

상태 규칙:
- `Proposed` — 쓰는 중. 결정 전.
- `Accepted` — 결정됨. 구현 여부는 별개(본문에 적는다).
- `Deprecated` — 더 이상 유효하지 않으나 대체 결정 없음.
- `Superseded by ADR-NNNN` — 새 결정이 대체함. 옛 문서 본문은 안 고친다.
