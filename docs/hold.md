# Hold (보류)

⚠️ **이 문서는 현재 상태가 아니다.** "보류"는 방향이 다른 두 종류를 다 포함한다 — 검토했지만 안 하기로 한 것(기각)과, 아직 안 했을 뿐인 것(미구현 비전). 실제로 뭘 만들었는지는 `docs/CHANGELOG.md`를 봐야 한다. 실제 진행은 여기 적힌 방향(MCP, Kafka/ES, Gemini 오디오 등)과 다르게 흘러간 부분이 많다 — 예를 들어 코칭 리포트는 여기 없던 "태그 기반 아키텍처"로 갔다.

## 검토했지만 안 한 것 (기각 이유 있음)

기술 선택(뭘 안 썼는지)은 여기, 코드 동작 관련 규칙(뭘 하면 안 되는지)은 `PROJECT.md`의 Important Constraints 참고.

### Kafka + Elasticsearch 로그 파이프라인
- 트래픽이 그 규모가 아님 — 1인 프로젝트 수준 트래픽에 분산 로그 파이프라인은 오버엔지니어링
- 운영 부담 — Kafka+ES 운영에 드는 인프라 비용/복잡도가 지금 예산·시간으로 감당 안 됨
- 필요해지면: MySQL 로그 테이블 + 집계 쿼리로 당분간 충분

### Redis (대신 Caffeine 인메모리 캐시 사용)
- 단일 인스턴스로만 운영 중이라 인스턴스 간 상태 공유(분산 캐시)가 아직 필요 없음
- 수평 확장하게 되면 그때 `RedisPracticeAttemptStore`로 교체 예정 (`PracticeAttemptStore` 인터페이스로 이미 분리해둠 — `AGENTS.md` 참고)

### Zero-Copy / Direct Buffer (JVM 힙 우회 전송)
- 개념: `FileChannel.transferTo()`나 off-heap 메모리로 커널 영역에서 직접 소켓 전송, GC 부하 0
- 기각 이유: 네이티브 메모리 해제를 직접 관리해야 해서 Native Memory Leak 위험. 작은 데이터는 할당 비용이 더 커서 오히려 손해. 현재 트래픽 규모에서 오버엔지니어링

### Lock-free 동시성 (LMAX Disruptor 스타일 Ring Buffer)
- 개념: `synchronized`/`ReentrantLock` 대신 CAS 기반 낙관적 동시성으로 나노초 단위 응답
- 기각 이유: 락 대신 스핀락으로 CPU 점유율이 100%까지 치솟을 수 있음, 코드 복잡도 대비 지금 트래픽엔 안 맞음. 웬만한 트래픽까진 `LinkedBlockingQueue` 등 일반 큐가 생산성 면에서 나음

(참고: **Structured Concurrency**는 같은 검토 목록에 있었지만 실제로 채택·적용됨 — `docs/CHANGELOG.md` 참고)

## 미구현 비전 (아직 안 했을 뿐)

### Product Ideas

**스낵형 학습 (Snack-sized Learning)**
- 문제: 기존 모의고사는 40분간 15문제를 한 번에 풀어야 하는 부담이 큼
- 해결: 출퇴근길이나 자투리 시간에 1개 콤보(2~3문제) 단위로 가볍게 연습 가능

**1:1 AI 밀착 튜터**
- 비전: 고액 과외의 개인 맞춤형 피드백을 경제적으로 제공
- 방식: OPIc 평가 기준에 맞춘 명확하고 일관된 피드백

**Voice Cloning 모범 답안 (Premium)**
- 아이디어: AI가 작성한 모범 답안을 사용자 자신의 목소리로 들려줌
- 효과: 심리적 친밀감 상승 및 쉐도잉(Shadowing) 학습 효과 극대화

### System Integration & Data Driven

- MCP Server 도입 — 백엔드 API와 AI의 유기적 결합 시도. 실제로는 안 만들어짐
- 개인화 추천 — 유저 데이터 분석 기반 취약 유형 집중 문제 추천

### Premium Features

- 멀티모달 전환 — 음성 뉘앙스(감정, 속도) 분석
- AI 발음/억양 코칭 — 오디오 파형 분석 기반 정밀 발음 교정
- 모바일 확장 — 웹을 넘어 모바일 앱 환경 지원

### 채점 항목 집중 연습 모드 (Focus Mode)

현재 연습은 항상 전체 항목(표현력/정확성/메인포인트/유창성/내용)을 동시에 평가한다. 특정 항목만 집중 연습하는 모드 구상:

- **메인포인트 집중**: mainPoint + content만 평가, "포인트가 있었나요? 흐름이 일관적였나요?" 피드백
- **어휘/표현 집중**: 형용사·감정·비유 사용 여부 중심, 개선 예시 제공
- 진입점: 홈화면 "집중 연습" 섹션, 학습분석 화면 "집중 연습하기" 버튼

### 유형별 연습 모드

OPIc 유형(묘사/경험/롤플레이 등)에 익숙해지면 주제가 바뀌어도 답변 패턴 재활용 가능. 특정 유형 문제만 뽑아 연습하는 엔드포인트 구상 (주제는 랜덤, 유형 고정). 진입점: 홈화면 "유형별 연습" 섹션, 학습분석 화면 "연습하기" 버튼.

### 복습 추천 로직

마지막 연습일 + 점수 기반으로 복습 간격을 조정하는 추천 로직. 학습분석 화면에서 "연습" 버튼으로 연결 예정이었으나 아직 없음.
